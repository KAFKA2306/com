# Source verification policy

Current public facts must be verified against current primary sources before they are used in decisions, analyses, issues, pull requests, or published artifacts. Start by searching current primary sources.

- Verify official names, dates, numbers, versions, and specifications.
- Remove any factual statement that cannot be confirmed.
- Distinguish event date, publication date, accounting period, forecast period, and observation date.
- Prefer official filings, documentation, standards, release notes, first-party announcements, and first-party datasets.
- Recheck the final result after drafting and remove stale or unsupported content.
- Cite exact URLs or connected-source references at the claim they support. Record the URL and observation date in the governing work item or target artifact.

Verify repository state through current GitHub data. Cite the exact file, issue, pull request, commit, workflow, release, or deployment. Use prior conversations and status summaries as pointers to that evidence.
