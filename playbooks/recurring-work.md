# Recurring-work playbook

## Define

Create a recurring-service issue and registry entry containing:

- purpose and target;
- cadence or condition;
- primary sources and freshness window;
- executor class;
- normal result format;
- failure and incident rules;
- pause and retirement conditions;
- privacy and cost constraints.

## Operate

- Keep routine successful results compact and link their evidence.
- Create an incident for incorrect output, missed execution, broken authentication, stale sources, deployment failure, or policy violation.
- Create a directive when code or configuration must change.
- Do not report a service as operational until an execution has been observed, unless the accepted scope explicitly ends at disabled installation.

## Review

Periodically check whether the service is still useful, accurate, affordable, non-duplicative, and attached to an active user decision. Retire services that only generate noise or repeatedly lack actionable evidence.
