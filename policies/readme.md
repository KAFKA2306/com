# README方針

この方針は、KAFKA2306配下で継続的に管理するリポジトリの`README.md`に適用します。

## 目的

READMEは、初見の人間がリポジトリを開いたときに、他の会話、Issue、AGENTS.md、過去の記憶へ依存せず、次を判断できる正準入口です。

- 何のためのリポジトリか
- 誰が何に使うのか
- 現在、何が実装済みか
- どこから利用、閲覧、実行できるか
- どのデータや成果物が正準か
- どうセットアップし、どう検証するか
- どこまでが公開され、何を保存してはいけないか
- 既知の制約、未完了、停止中の機能は何か

## 言語

- README本文の主要言語は日本語とする。
- 固有名詞、API名、コマンド、コード、規格名は正式な英語表記を保持してよい。
- 海外利用者向け英語文書が必要な場合は`README.en.md`などへ分離する。
- 日本語READMEの冒頭を英語の宣伝文だけにしない。

## 必須項目

規模や用途に応じて統合してよいが、次の情報を欠落させない。

1. **概要** — 目的、対象ユーザー、解決する問題
2. **現在できること** — 実装済み機能と公開状態
3. **利用方法** — 公開URL、CLI、UI、APIなどの入口
4. **セットアップ** — 必要環境、依存関係、初期化手順
5. **主要コマンド** — 開発、生成、検証、公開、復旧
6. **構造** — 主要ディレクトリと責務
7. **データと成果物** — 正準、生成物、キャッシュ、外部由来データ
8. **検証** — unit、lint、schema、E2E、公開確認など
9. **運用** — 定期処理、更新経路、監視、障害時の確認先
10. **セキュリティ** — 秘密情報、個人情報、公開境界
11. **既知の制約** — 未完了、環境依存、保証しない範囲
12. **関連文書** — AGENTS.md、ADR、仕様、runbookなど
13. **ライセンス** — コード、データ、画像、第三者素材

存在しない項目を形式的に作らない。例えば、公開サービスがない場合は「公開URLなし」と明記する。

## 最新性

- READMEはリポジトリの現在のmainまたはdefault branchと照合して更新する。
- 日付だけを書き換えて最新を装わない。
- 実装されていない機能、終了したサービス、古いURLを現在形で書かない。
- 数値、件数、バージョン、公開URL、対応環境は変更時に再確認する。
- 自動生成された統計をREADMEへ固定値として書く場合は、計測日と生成元を明記する。

## 人間向けREADMEとエージェント向けAGENTS.md

### README.md

- 背景と目的
- システム全体像
- 人間が使う手順
- 運用と制約
- 関連文書への案内

### AGENTS.md

- エージェントが変更時に守る順序
- 禁止操作
- 完了ゲート
- ファイル配置規則
- エージェント固有の検証手順

AGENTS.mdにしか書かれていない重要な人間向け情報はREADMEへ移す。READMEへ長大なエージェント命令を重複させない。

## 事実性

READMEは宣伝文ではなく、現在状態の説明書である。

- 「完全対応」「自動」「安全」「高精度」などの表現は、検証条件を説明できる場合だけ使う。
- PR作成済みを実装完了と表現しない。
- CI成功を公開確認済みと表現しない。
- 設定済みのscheduleを実稼働中と表現しない。
- 外部データを利用する場合は、出典、取得日、利用条件、欠損時の挙動を説明する。

## 小規模・停止中・アーカイブ候補のリポジトリ

コードが少ない、実験が停止している、別リポジトリへ統合された場合も、READMEを空にしない。

最低限、次を記載する。

- 何を試したリポジトリか
- 現在の状態
- 後継または正準リポジトリ
- 再利用可能な内容
- 実行可能か、未検証か
- archiveまたは削除を検討すべきか

上流OSSのforkやsnapshotは、独自製品のように書き換えない。上流、fork理由、差分、同期方針、ライセンスを明示する。

## 更新手順

1. default branchのREADME、主要設定、ディレクトリ、最近のmergeを確認する。
2. 公開URLや主要コマンドを実測またはCIで確認する。
3. READMEを更新する。
4. リンク、コマンド、記述と実体の整合を検証する。
5. PRへ変更理由と確認結果を記録する。
6. merge後にdefault branchのREADMEを読み戻す。

## 完了条件

README更新を完了とするには、次を満たす。

- 日本語で人間が主要責務を理解できる
- リポジトリ実体と矛盾しない
- 重要な入口と検証方法が記載されている
- 既知の制約を隠していない
- PRまたはcommitがdefault branchへ反映されている
- 必要なCIが成功している

READMEは継続的に更新する。リポジトリの責務や実行方法を変えるPRでは、README更新の要否を必ず確認する。
